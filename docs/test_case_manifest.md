# 固定样例清单

当前仓库内固定样例分为两层：

- 24 条核心样例：用于重复件召回、LLM 判断和新线索提取
- 7 条排序验证扩展样例：用于同人不同事、同事不同人、同地不同部门、近义改写、简称别名等排序场景

系统化排序验证的结构化清单见 `docs/ranking_eval_manifest.json`。

## 重点场景

1. 太原市万柏林区住建工程收受礼金
   - 主样例：`CASE-0001`
   - 近重复：`CASE-0002`
   - 可挖掘线索：`CASE-0003`
   - 预期：查询“王建国 城改项目 收受礼金 指定亲属承包工程”时，应命中 `CASE-0001`、`CASE-0002`、`CASE-0003`，并从 `CASE-0003` 挖掘“亲属公司承揽工程”线索，返回的 clue 应包含 `source_case_id=CASE-0003`

2. 大同市教育采购回扣
   - 主样例：`CASE-0006`
   - 近重复：`CASE-0007`
   - 预期：查询“赵志强 指定供应商 校服采购 回扣”时，应命中 `CASE-0006`、`CASE-0007`

3. 晋中市干部调整收礼
   - 主样例：`CASE-0012`
   - 近重复：`CASE-0013`
   - 预期：查询“孙志明 干部调岗 晋升 收礼 打招呼”时，应命中 `CASE-0012`、`CASE-0013`

4. 非重复对照
   - 对照样例：`CASE-0024`
   - 预期：当查询仅涉及“审批拖延”而无收礼、项目操控等事实时，不应被判为太原市王建国或李海峰相关重复件
   - 预期：`new_clues` 也应为空数组

## 覆盖类型

- 明确重复件：`CASE-0001~0003`、`CASE-0006~0007`、`CASE-0012~0013`
- 同人不同表述：`CASE-0004~0005`、`CASE-0016~0017`
- 同地不同人：`CASE-0001` 对比 `CASE-0024`
- 跨时间窗口：`CASE-0010` 与 `CASE-0011`
- 新线索延展：`CASE-0003`、`CASE-0019`
